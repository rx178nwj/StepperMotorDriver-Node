| 版 | 0.11（2026-10-20：位置決めの減速と目標変更（FR-MOT-03・04）、SYNC_POSITION の値の範囲（FR-POS-06・07）を明確化） |

**0.11 での変更**：ホスト単体テスト（フェーズ C）で見つかった実装との差を、次のとおり決めた。(1) FR-MOT-03：位置決めで一度減速に入ったら、目標が変わるまで減速を続け、減速中に速度を上げない（速度は 加速→一定→減速 の順で、減速中は単調に下がる）。(2) FR-MOT-04：動作中に、残りの距離が減速距離より短い目標へ変えた場合は、減速度 d を守って減速し、目標を行き過ぎて停止してから、逆方向に目標へ戻る（FR-MOT-06 と同じく、停止してから DIR を切り替える）。減速度の上限を超えて目標で急停止しない。(3) FR-POS-06・07：SYNC_POSITION の結果は 0〜N−1（N = GEAR_RATIO × STEPS_PER_REV × MICROSTEP）とし、四捨五入で N になった場合は 0 にする。N が符号付き 32bit の最大値を超える設定では、SYNC_POSITION（自動を含む）を実行せず CMD_RESULT=2 とする。

**0.10 での変更**：実装との差を解消し、P2 の要求を補足した。(1) FR-MON-04：励磁中の VM 範囲外は、10 ms 周期で 2 回連続して範囲外になったとき（最大約 20 ms）に FAULT とする。1 回の判定では ADC のノイズやモータ起動時の電圧低下で誤検出しやすいため。(2) FR-MON-08：LO 異常（OPD・ISD・TSD）は出力 OFF では原因を確認できないため、CLEAR_FAULT で解除する。原因が残っていれば、次の ENABLE 後に LO 検出で再び FAULT になる。温度と VM は従来どおり、原因が残っていれば解除しない。(3) FR-USB-52：CAN_REQUEST の書き込み（OP 0x01）とブロードキャスト（CAN_ID 0x000）は再送しない。FW が実行して応答だけが失われた場合の二重実行を防ぐため。(4) 3.8 節：ACCEL・DECEL の範囲（1〜10,000,000 step/s²）と、MAX_SPEED・START_SPEED・JOG_SPEED の範囲（1〜100,000 step/s）をレジスタ表に追記した。(5) FR-COM-12：未送信の異常通知を新しい通知で上書きした場合も tx_dropped に計上する。(6) P2 の補足：FR-USB-62（DFU デバイスの検出方法）、FR-HOME-03（進行方向の判定）、FR-BL-04（移行フラグの置き場所）。FR-USB-33 は変更しない（FW を仕様どおり、ECC エラーの時点で読み出しを中止するように修正した）。

**0.9 での変更**：P2 の要求を追加した。(1) AGC（3.11 節）：FLAGS bit3 で ON/OFF し、励磁 OFF（EN=Low）の間だけ AGC0/AGC1 を切り替える。CLIM・BOOST・FLIM・LTH は基板のストラップで固定。(2) J10 入力（3.12 節）：J10_MODE（0x59）で PA15/PA1 を、未使用／A/B エンコーダ（TIM2、読み出しのみ）／原点・リミットスイッチに切り替える。原点・リミットでは、リミット側への移動の即停止と、原点復帰コマンド（COMMAND 11・12）を行う。(3) ブートローダ移行（3.13 節）：USB のコマンド ENTER_BOOTLOADER（0x50）で、BOOT0 を押さずに ROM の USB DFU へ移る。IWDG を止められないため、ソフトウェアリセットを経由し、IWDG を起動する前に ROM へ移る。レジスタ 0x1E、0x59〜0x5F、COMMAND 11・12、FLAGS bit3・bit4、USB コマンド 0x50、nemadbg の `dfu` を追加した。保存レコードは版 3 とし、大きさ（64 バイト）は変えない。

**0.8 での変更**：(1) FR-USB-05 に、応答を送れない状態（送信が 50 ms 以上詰まっている）で受けた要求は実行せず捨てることを追記した。「要求 1 つにつき応答 1 つ。応答を捨てた要求は実行しない」ので、PC はタイムアウトで再送してよい。(2) 未送信のイベントを新しいイベントで上書きした場合も、破棄として tx_dropped に計上する。(3) PC 側ツール（`firmware/tools/`、Python CLI `nemadbg`）を 3.9.7 節として追加し、P2 から P1 へ前倒しする。(4) ホスト PC での単体テスト（`firmware/tests/host/`）を追加する（試験 29）。

**0.7 での変更**：出力軸の絶対位置センサ AS5600 の要求を追加する（3.10 節）。構成は モータ → ギヤ（20:1 または 40:1）→ 磁石 → AS5600 で、ギヤ後の軸の角度を I2C1（J9）から読み、(1) 軸の初期位置の判定、(2) 軸の絶対位置の把握に使う。出力軸の可動範囲は 1 回転未満とする。角度はステップ位置とは別のレジスタで公開し、モータ制御（脱調検出・閉ループ補正）には使わない。センサ未接続・読み出し失敗でも FAULT にせず、無効値を返して動作を続ける。初期位置は、起動後にセンサが最初に有効になった時点（モータ未動作のとき）に自動で、またはコマンド SYNC_POSITION（COMMAND 10）で、センサ角度からステップ位置に設定する。AS5600 の DIR ピンは J10.5（PA7）に接続し、PA7 は設定（PA7_MODE）で AD_IN（アナログ入力）／DIR（出力）／Z（デジタル入力）に切り替える。レジスタ 0x19〜0x1D（読み出し）、0x54〜0x58（設定）、COMMAND 10 を追加。

**0.6 での変更**：実装に合わせて次を追記した。(1) FR-USB-06 と FR-COM-11 の応答時間は、Flash 消去中（SAVE・LOAD・FACTORY、最大約 25 ms、FR-NV-07）は適用しない。(2) FR-COM-12 に、他の CAN ノードが無く ACK が得られない間は応答を破棄する制約を追記した。

**0.5 での変更**：USB（J6 Type-C、USB FS の CDC 仮想 COM ポート）を P2 から P1 へ移し、デバッグと内部設定に使う（3.9 節）。CCP（CAN Calibration Protocol）を参考にしたバイナリプロトコルで、(1) CAN で実装する通信（要求・応答・ブロードキャスト・異常通知）を USB 経由で自局に対してすべて実行でき、(2) 内部 RAM をアドレス指定（CCP 方式、PC 側で ELF から名前を解決）またはファームウェア内の名前表による名前指定でダンプできる。RAM への書き込みは行わない（読み出し専用）。USB から CAN バスへの送受信（USB-CAN ブリッジ）は行わない。

**0.4 での変更**：PC15 を `DRV_MO`（入力）から `CAN_S`（GPIO 出力）へ変更する。CAN_S は TJA1441AT の S（Pin 8）につながり、Low でノーマル、High でサイレントモード。TB67S249 の MO は未接続、MO のプルアップ（R36）は削除済みで、MO の公開（FR-DRV-09、STATUS bit1）は廃止する（STATUS bit1 は予約、常に 0）。CAN 起動前に CAN_S を Low にする要件を追加（FR-COM-14）。回路図は反映済み。

**0.3 での変更**：上位通信を CAN に変更する。PCA9615 と I2C2 を削除し、CAN トランシーバ TJA1441AT を追加する。CAN1 を PB8/PB9 に割り当て、それまで PB8/PB9 にあった DRV_AGC0/1 は PB10/PB11 へ移す。バス終端 120Ω は DIP スイッチで切り替える。レジスタマップ（3.8 節）は変えず、転送方式だけを CAN フレームに置き換える。**回路図への反映は未実施**（本書のピン割り当ては変更後の計画値）。

**0.2 での変更**：VREF の分圧抵抗 R32 を未実装とし DAC 出力をそのまま VREF とする。対象モータは 3A 品。TH1 は Murata NCP18XH103F03RB。モータ設定を不揮発保存し、外部通信で設定できるようにする（3.7 節）。

ピン割り当て・周辺定数は、上記回路図から KiCad 10 でネットリストを出力して確認した。設計メモ `schematic/stm32l433_tb67s249_connection.md` の参照番号は再アノテーション前のため、本書では **現在の回路図の参照番号** を用いる。

## 1. 目的と範囲

1 枚の基板で 1 台のバイポーラステッピングモータ（NEMA23 想定）を駆動する。上位マスターから CAN バス（トランシーバ TJA1441AT）経由で最大 8 台を制御する。

| フェーズ | 内容 |
|---|---|
| **P1 基本機能（本版で実装）** | クロック・GPIO 初期化、ドライバ制御（励磁・分割・電流）、台形加減速パルス生成、電源/温度監視、異常検出と保護、DIP アドレス、CAN 通信、LED、ローカルジョグスイッチ、ウォッチドッグ、**モータ設定の不揮発保存と通信による設定**、**USB CDC によるデバッグ・設定通信（3.9 節）**、**USB の PC 側ツール（CLI、3.9.7 節）** |
| P2 拡張 | 出力軸の位置センサ（J9、AS5600、3.10 節）、AGC（脱調防止）の運用（3.11 節）、J10 のエンコーダ／原点・リミット入力（3.12 節）、ROM ブートローダ（USB DFU）への移行（3.13 節） |

## 3. 機能要求

### 3.1 起動・システム（P1）

| ID | 要求 |
|---|---|
| FR-SYS-01 | システムクロックは HSI16 → PLL で 80 MHz とする（HSE/LSE は使用しない。PH0/PH1/PC14/PC15 を GPIO として使うため） |
| FR-SYS-02 | リセット直後、ドライバを安全状態にする：EN=Low、DMODE=000（スタンバイ）、RESET=Low、AGC=00、CLK=Low、DAC 出力 0 |
| FR-SYS-03 | 起動時に ADC キャリブレーションを行う |
| FR-SYS-04 | 独立ウォッチドッグ（IWDG）をタイムアウト約 500 ms で動作させ、メインループで更新する |
| FR-SYS-05 | 起動時に DIP スイッチ（ADDR0〜2）を読み、`ID = ADDR0 + 2·ADDR1 + 4·ADDR2` を確定する。動作中の変更は再起動まで反映しない |

### 3.2 ドライバ制御（P1）

| ID | 要求 |
|---|---|
| FR-DRV-01 | ステップ分割を 1, 2, 4, 8, 16, 32 から選択できる。DMODE への対応は下表（データシート表「DMODE のファンクション」）。1/2 は (a) 型を使用する |
| FR-DRV-02 | スタンバイ解除（DMODE≠000）後、7.5 µs 以上待ってから他の信号を変化させる（FW では 20 µs 以上待つ） |
| FR-DRV-03 | モータ電流は mA 単位で指定し、DAC コードへ換算する：`V_DAC = VREF = I/1.25`、`code = V_DAC / VDDA × 4095`。VDDA は VREFINT で補正する |
| FR-DRV-04 | 電流設定の範囲は 250〜3000 mA。上限 3000 mA は対象モータ定格と J3（JST XH、AWG22 で 3A）の定格に合わせる。範囲外の設定値は受け付けない |
| FR-DRV-05 | 電流 0 は DAC 下限（バッファ有効時 約 0.2V = 250 mA 相当）で実現できないため、励磁 OFF は EN=Low で行う |
| FR-DRV-05a | R32 がないため DAC を停止すると VREF が浮く。DAC は初期化後停止せず、不要時は最小出力（コード 0）にする |
| FR-DRV-06 | 停止後、設定時間（既定 500 ms）経過したら保持電流へ切り替える。動作開始時は運転電流へ戻してから最初のパルスを出す |
| FR-DRV-07 | AGC0/AGC1 は P1 では Low 固定（AGC 無効）。動作中に AGC0 を切り替えない（データシート注意）。P2 の運用は 3.11 節 |
| FR-DRV-08 | 電気角初期化コマンドで RESET を 10 µs High にする（停止中のみ） |
| FR-DRV-09 | （廃止。0.4 で MO を未接続としたため、MO の状態は公開しない） |

### 3.3 パルス生成・動作制御（P1）

| ID | 要求 |
|---|---|
| FR-MOT-01 | TIM1_CH1 のハードウェア PWM で CLK を生成する。パルス幅 High ≥ 1 µs、Low ≥ 1 µs（データシート最小 500 ns） |
| FR-MOT-02 | ステップ速度範囲：1〜100,000 step/s（マイクロステップ単位）。TB67S249 の入力上限 1 MHz に対して CPU 負荷で制限する |
| FR-MOT-03 | 台形加減速：開始速度 v0、最高速度 vmax、加速度 a、減速度 d（step/s²）で 1 ステップごとに速度を更新する（`v² ← v² ± 2a`）。位置決めで一度減速に入ったら、目標の変更・停止指令があるまで減速を続け、減速中に速度を上げない（速度は 加速→一定→減速 の順で、減速中は単調に下がる。最高速度に届かない短い移動でも同じ） |
| FR-MOT-04 | 位置決めモード：絶対目標位置・相対移動量を指定し、減速距離 `v²/2d` を見込んで目標で停止する。動作中に、残りの距離が減速距離より短い目標へ変えた場合は、減速度 d を守って減速して目標を行き過ぎ、停止してから逆方向へ目標に戻る（FR-MOT-06 と同じく DIR は停止中に切り替える）。減速度の上限を超えて目標で急停止しない |
| FR-MOT-05 | 速度モード：符号付き目標速度で連続回転する。速度変更は加減速を伴う |

### 3.4 監視・保護（P1）

| ID | 要求 |
|---|---|
| FR-MON-01 | VM を 10 ms 周期で計測する：`VM = code/4095 × VDDA × 19`。サンプル時間は 247.5 サイクル |
| FR-MON-02 | VM 正常範囲は 10.5〜28.0 V（ヒステリシス 0.5 V）。入力定格 12〜24 V、TB67S249 下限 10 V、AP63205 推奨上限 32 V に基づく |
| FR-MON-03 | VM が正常範囲で 50 ms 以上安定するまで、ドライバをスタンバイから解除しない（USB 給電のみでは VM≈0V となり励磁しない） |
| FR-MON-04 | 励磁中に VM が範囲外になったら、パルスを即停止し EN=Low として異常（低電圧 / 過電圧）をラッチする。判定は 10 ms 周期で 2 回連続して範囲外になったとき（検出まで最大約 20 ms）とする。1 回の判定では、ADC のノイズやモータ起動時の電圧低下による誤検出が起きやすいため |

|---|---|---|

| H | L | 負荷オープン（OPD） |
| L | H | 過電流（ISD） |

### 3.9 USB 通信（P1：デバッグ・内部設定）

PC と USB で接続し、デバッグと内部設定に使う。プロトコルは CCP（CAN Calibration Protocol, ASAM）を参考にし、要求（CCP の CRO 相当）に対して必ず 1 つの応答（DTO 相当）を返す。用途は次の 2 つ。

1. **CAN 通信の代行**：3.8 節で CAN に実装する通信（書き込み・読み出し要求、ブロードキャスト指令、不正要求への応答、異常通知）を、USB 経由で自局に対してすべて実行できる。CAN バスが無くても CAN の処理系をデバッグでき、レジスタ書き込み＋SAVE_SETTINGS で内部設定もできる。
2. **内部 RAM のダンプ**：CCP と同じアドレス指定（SET_MTA＋UPLOAD）と、ファームウェアが持つ名前表による名前指定の両方でメモリを読み出す。

USB から CAN バスへのフレーム送信・バス上のフレームの転送（USB-CAN ブリッジ）は行わない。メモリへの書き込み（CCP の DNLOAD 相当）も行わない。

#### 3.9.1 物理層・全体

|---|---|
| FR-USB-01 | USB FS デバイス（PA11/PA12）を CDC ACM（仮想 COM ポート）で動作させる。ボーレート等の回線設定は無視する。USB クロックは HSI48 を CRS で USB SOF に同期させる（CubeMX 設定済み） |
| FR-USB-02 | ディスクリプタ：VID/PID は開発中 ST 既定（0x0483/0x5740）、製品文字列「NEMA23 Stepper Driver」、シリアル番号は MCU の UID から生成し、複数台を PC 側で区別できるようにする |
| FR-USB-03 | USB 給電のみ（VM 無し、NO_VM 状態）でも USB 通信は動作する |
| FR-USB-04 | USB の割り込み優先度は TIM1（パルス生成）・EXTI（LO1/LO2）・CAN より低くする。割り込みでは受信データをリングバッファに積むだけとし、フレーム解析・応答生成はメインループで行う（NFR-02、NFR-03 を損なわない） |

| FR-USB-07 | VBUS 検出は使わない（PA9 は DRV_DIR に使用）。USB バスリセット・サスペンドでセッションを切断状態にする |

#### 3.9.2 フレーム形式

CDC はバイトストリームのため、次のフレームで区切る。

```text
[SOF=0xA5][LEN][BODY: LEN バイト][CRC16 下位][CRC16 上位]
```

| ID | 要求 |
|---|---|
| FR-USB-10 | LEN は BODY のバイト数で 2〜250。CRC16 は CRC-16/CCITT-FALSE（多項式 0x1021、初期値 0xFFFF、反転なし）を LEN と BODY にかけたもの。多バイト値はすべてリトルエンディアン |
| FR-USB-11 | 受信側は SOF を待ち、LEN が範囲外なら SOF の次のバイトから SOF を探し直す。フレーム途中で 20 ms 以上バイトが途切れたら受信途中のフレームを捨てる。CRC 不一致のフレームは応答せずに捨てる（PC はタイムアウトで再送する） |
| FR-USB-12 | 要求 BODY（CRO 相当）：`[CMD][CTR][PARAM…]`。CTR は PC が要求ごとに増やす 8bit カウンタ |
| FR-USB-13 | 応答 BODY（DTO 相当）：`[PID=0xFF][ERR][CTR][DATA…]`。CTR は要求の値をそのまま返す。ERR≠0x00 のとき DATA は付けない |
| FR-USB-14 | イベント BODY：`[PID=0xFE][EVT][DATA…]`（基板から非同期に送る）。セッション接続中だけ送る |
| FR-USB-15 | PC は応答を受け取ってから次の要求を送る（同時に 1 要求、CCP と同じ）。ファームウェアは受信バッファに 2 フレーム以上を保持できること |

エラーコード（ERR、CCP のコードに合わせる）：

| ERR | 意味 | 主な発生条件 |
|---|---|---|
| 0x00 | 正常（ACK） | |
| 0x30 | 未定義コマンド | CMD が未定義 |
| 0x31 | コマンド構文エラー | BODY 長がコマンドの形式と合わない |
| 0x32 | パラメータ範囲外 | SIZE・INDEX・CAN_ID・DLC が範囲外 |
| 0x33 | アクセス拒否 | 読み出し許可領域外のアドレス（FR-USB-31）、ENABLED 中の ENTER_BOOTLOADER（FR-BL-02） |
| 0x35 | アクセスロック | CONNECT していない |
| 0x36 | リソースなし | 名前表に該当する名前がない、Flash 読み出しで ECC エラー |

#### 3.9.3 コマンド

| CMD | 名前 | 要求 PARAM | 応答 DATA | 備考 |
|---|---|---|---|---|
| 0x01 | CONNECT | なし | `[PROTO_MAJOR][PROTO_MINOR][DEVICE_ID][FW_MAJOR][FW_MINOR][BOARD_ID][MAX_LEN]` | セッション開始。MAX_LEN は受け付ける最大 LEN（250） |
| 0x07 | DISCONNECT | なし | なし | セッション終了。以後イベントを送らない |
| 0x1B | GET_VERSION | なし | `[PROTO_MAJOR][PROTO_MINOR]` | 未接続でも受け付ける。本版は 1.0 |
| 0x17 | EXCHANGE_ID | なし | `[N][BUILD_ID N B]` | ELF の GNU build-id（SHA1、N=20）。PC が ELF との一致を確認する |
| 0x02 | SET_MTA | `[ADDR u32]` | なし | メモリ転送アドレス（MTA）を設定 |
| 0x04 | UPLOAD | `[SIZE]`（1〜240） | `[DATA SIZE B]` | MTA から読み出し、成功時 MTA += SIZE |
| 0x0F | SHORT_UP | `[SIZE][ADDR u32]` | `[DATA SIZE B]` | 指定アドレスから読み出し。MTA は変えない |
| 0x20 | SYM_COUNT | なし | `[COUNT u16]` | 名前表の登録数 |
| 0x21 | SYM_INFO | `[INDEX u16]` | `[ADDR u32][TYPE][NUM u16][NLEN][NAME NLEN B]` | INDEX 番目の登録内容 |
| 0x22 | SYM_FIND | `[NLEN][NAME NLEN B]` | `[INDEX u16][ADDR u32][TYPE][NUM u16]` | 名前で検索（大文字小文字を区別、完全一致） |
| 0x23 | SYM_UPLOAD | `[NLEN][NAME NLEN B][OFFSET u16][SIZE]` | `[DATA SIZE B]` | 名前指定で読み出し。SIZE=0 は変数全体（240 B 超なら 0x32） |
| 0x40 | CAN_REQUEST | `[CAN_ID u16][DLC][DATA DLC B]` | `[N]` に続き N 個の `[CAN_ID u16][DLC][DATA DLC B]` | CAN フレームの受信を模擬し、基板が返すフレームを返す（FR-USB-40） |
| 0x50 | ENTER_BOOTLOADER | `[KEY u32]`（0x544F4F42、"BOOT"） | なし | ROM ブートローダ（USB DFU）へ移る（P2、3.13 節）。KEY 不一致は 0x32 |

- CONNECT 前は CONNECT・GET_VERSION 以外に ERR 0x35 を返す。
- イベント EVT=0x01（CAN_FRAME）：DATA は `[CAN_ID u16][DLC][DATA DLC B]`。FR-COM-10 の異常通知（`0x080 + ID`）を CAN に送信するとき、同じ内容を USB にも送る。

#### 3.9.4 メモリ読み出し（アドレス指定・CCP 方式）

| ID | 要求 |
|---|---|
| FR-USB-30 | アドレス指定の読み出しは、PC 側が ELF（シンボル表・DWARF）または .map から名前をアドレス・サイズに解決して行う（CCP で A2L を使うのと同じ）。PC は EXCHANGE_ID の build-id と ELF の build-id が一致することを確認してから使う |

#### 3.9.6 CAN 通信の代行

| ID | 要求 |
|---|---|
| FR-USB-40 | CAN_REQUEST は、指定した CAN フレームを CAN1 で受信したのと同じ処理系（受信フィルタ判定 FR-COM-04 を含む）に渡す。その結果、基板が CAN に送信するはずのフレーム（`0x180 + ID` の応答、`0xFF` 不正応答）は **CAN バスには送らず** USB の応答 DATA に入れて返す。応答が無い場合（ブロードキャスト、他局宛て、フィルタで捨てたフレーム）は N=0 |

### 3.10 出力軸の位置センサ（P2：AS5600）

構成は モータ → ギヤ（40:1 または 20:1）→ 磁石 → AS5600。センサはギヤ後の出力軸の角度（1 回転 4096 カウント）を測る。用途は (1) 軸の初期位置の判定、(2) 軸の絶対位置の把握で、モータ制御（脱調検出・閉ループ補正）には使わない。

| ID | 要求 |
|---|---|
| FR-POS-01 | AS5600 を J9（I2C1：PB6 SCL / PB7 SDA、R40・R43 4.7kΩ プルアップ）に接続する。7bit アドレスは 0x36 固定。I2C の速度は 400 kHz 以下 |
| FR-POS-02 | 10 ms 周期で STATUS（0x0B）と RAW ANGLE（0x0C・0x0D、12bit）を読む。STATUS の MD（bit5）が 0 のとき（磁石なし）は無効とする。MH（bit3）・ML（bit4）は SENSOR_STATUS に写すだけで、無効にはしない |
| FR-POS-03 | I2C の通信が TIM1（パルス生成）・EXTI（LO1/LO2）・CAN の処理を妨げないこと。割り込み優先度はこれらより低くし、メインループを止める時間は 1 トランザクションあたり 1 ms 以内とし、超えたら失敗として扱う（NFR-02、NFR-03、FR-COM-11 を損なわない） |
| FR-POS-04 | センサが未接続または読み出しに失敗した場合、FAULT にせず動作を続ける。3 回連続で失敗したら無効とし、SENSOR_RAW・SHAFT_ANGLE を 0xFFFF、SENSOR_STATUS の bit3 を 1 にする。無効の間は 1 秒ごとに再接続を試み、成功したら有効に戻す。I2C バスが固着した場合は復帰させる（SCL を最大 9 クロック出す） |
| FR-POS-05 | 出力軸角度：`a = (RAW − SENSOR_OFFSET) mod 4096`、`SHAFT_ANGLE = a × 36000 / 4096`（四捨五入、0〜35999）。角度の増える方向は AS5600 の DIR ピンのレベルで決まる（PA7_MODE=1 なら FLAGS bit2、それ以外は基板上の DIR の固定。H-12）。ファームウェアでは反転しない |
| FR-POS-06 | COMMAND 10（SYNC_POSITION、初期位置を設定する初期化コマンド）：現在位置（POSITION）を `a × GEAR_RATIO × STEPS_PER_REV × MICROSTEP / 4096`（四捨五入）に設定し、SENSOR_STATUS の bit4 を 1 にする。計算は 64bit で行う。結果は 0〜N−1（N = GEAR_RATIO × STEPS_PER_REV × MICROSTEP、出力軸 1 回転分のステップ数）とし、四捨五入で N になった場合は 0 にする。N が符号付き 32bit の最大値（2147483647）を超える設定では実行せず CMD_RESULT=2（起動時の自動実行（FR-POS-09）も行わない）。MOVING 中は拒否（CMD_RESULT=1）、センサ無効のときは実行せず CMD_RESULT=3。SET_POSITION と同様に、停止中のみ受け付ける |
| FR-POS-07 | 出力軸の可動範囲は 1 回転未満とする（U-10、確定）。SYNC_POSITION の後、POSITION は出力軸 1 回転分のステップ数 `GEAR_RATIO × STEPS_PER_REV × MICROSTEP` の範囲内（0〜N−1）の軸の絶対位置になる。可動範囲が角度 0 をまたぐ場合は、SENSOR_OFFSET で角度 0 を可動範囲の外へずらす。POSITION が増える方向と SHAFT_ANGLE が増える方向が一致しないときは、FLAGS bit2 で合わせる（変更後は SYNC_POSITION をやり直す） |
| FR-POS-08 | GEAR_RATIO（1〜1000）・SENSOR_OFFSET（0〜4095）・PA7_MODE（0〜2）・FLAGS bit2 は不揮発保存の対象とする（FR-NV-01）。保存レコードは 64 バイトに収める（収まらない場合は版を上げ、版の古い保存レコードは新項目を既定値で補う）。工場出荷値は 3.8 節のレジスタ表の既定値 |
| FR-POS-09 | 起動後、最初にセンサが有効になった時点で、モータが一度も動いておらず（パルス未出力）、POSITION も SET_POSITION で再定義されていなければ、自動的に SYNC_POSITION と同じ処理を行う（U-12、確定）。モータが動いた後にセンサが有効になった場合は自動では行わず、COMMAND 10 を待つ。センサが無効のままなら POSITION は 0 のまま、SENSOR_STATUS の bit4 は 0 |
| FR-POS-10 | USB の名前表（FR-USB-37）に、センサの RAW 値、状態、出力軸角度、I2C の成功・失敗回数、PA7_MODE、Z 入力レベルを登録する |
| FR-POS-11 | PA7（J10.5）は PA7_MODE で機能を切り替える（FR-NV の保存対象）。起動時は設定を読み込んでから、保存されたモードに設定する（それまではリセット時のアナログ入力のまま）。<br>**0=AD_IN**：アナログ入力。ADC1_IN12 を計測して AD_IN_MV に出す。<br>**1=DIR**：GPIO 出力（プッシュプル・低速・プルなし）で、AS5600 の DIR ピンを FLAGS bit2 のレベルで駆動する（0=Low：磁石側から見て時計回りで RAW が増える、1=High：反時計回りで増える。AS5600 データシートによる）。FLAGS bit2 を書いたら即時にレベルを変える。変更後は SYNC_POSITION をやり直す。<br>**2=Z**：GPIO 入力（プルなし）で、レベルを SENSOR_STATUS bit5 に出す。10 ms 周期で読むだけで、エッジ検出や割り込みは行わない。<br>モードを書き換えたとき、PA7 は一度アナログに戻してから新しい機能を設定する。モードが 0 以外のとき AD_IN の ADC 計測は行わず AD_IN_MV は 0xFFFF を返す |

### 3.11 AGC（P2：脱調防止）

TB67S249 の AGC（Active Gain Control）は、VREF で決めた電流を上限に、負荷トルクに応じてドライバがモータ電流を段階的に下げる機能。ファームウェアは ON/OFF だけを制御し、動作の細かい設定は基板のストラップ抵抗で固定する。根拠は TB67S249FTG データシート（2017-08-18 版、9〜13 章）。

| ID | 要求 |
|---|---|
| FR-AGC-01 | AGC の ON/OFF を FLAGS bit3（0=OFF、1=ON、既定 0）で設定する。FR-NV の保存対象とする |
| FR-AGC-02 | AGC0 と AGC1 は常に同じレベルで駆動する：ON は (High, High)、OFF は (Low, Low)。データシートの (High, Low)（動作中に ON/OFF を切り替える用途。アプリケーションノートが要る）は使わない |
| FR-AGC-03 | AGC0/AGC1 は、励磁 OFF（EN=Low）の間だけ変える（データシート「動作中に AGC0 は切り替えない」）。ENABLED 中に FLAGS bit3 を変える書き込みは、FLAGS 全体を反映せず CMD_RESULT=1 とする。NO_VM・DISABLED・FAULT 中の書き込みは即時に端子へ反映する。ただし、スタンバイ解除の直後は FR-DRV-02 の待ち時間（20 µs）を過ぎてから変える。起動時は、設定を読み込んでからスタンバイを解除する前に、保存値を端子へ出す。ENABLED 中の LOAD・FACTORY（励磁したままの停止で受け付ける、FR-NV-07）で bit3 が変わる場合は、RAM の設定は変えるが端子は変えず、次に EN=Low になったときに端子へ反映する |
| FR-AGC-04 | ストラップは次のとおり固定（基板）：CLIM0=High（R8 0Ω で VCC）、CLIM1=VCC プルアップ 100 kΩ（R12）→ 電流下限 IOUT×75%。BOOST=VCC プルアップ 100 kΩ（R16）→ 最大 7 段階補正。FLIM=VCC プルアップ 100 kΩ（R21）→ CLK 周波数が 450 Hz × 分割数（1/16 で 7.2 kHz）未満では AGC 無効。LTH=GND プルダウン 100 kΩ（R20）→ 標準感度。変更は抵抗の付け替えで行い、ファームウェアの設定項目にしない |
| FR-AGC-05 | AGC が有効になるのは FR-AGC-04 の周波数以上だけで、停止中・保持電流中・低速では VREF の電流がそのまま流れる。AGC が実際に電流を下げているかはドライバから読めないため、状態として公開しない |
| FR-AGC-06 | AGC は LO1/LO2 の異常検出（FR-MON-05）と独立とし、AGC の ON/OFF で保護の動作を変えない |

注：工場出荷値（分割 16、最高速度 3200 step/s）は FLIM のしきい値（7.2 kHz）を下回るため、AGC を ON にしても効かない。AGC を使う場合は、運転速度をしきい値以上にするか、FLIM の抵抗を変える（U-14）。

### 3.12 J10 入力（P2：エンコーダ／原点・リミット）

J10.3（PA15、ENC_A_HOME1）と J10.4（PA1、ENC_B_HOME2）を、設定 J10_MODE で A/B エンコーダ入力か原点・リミットスイッチ入力に切り替える。J10 には保護回路・外付けのプル抵抗がなく、J10.1 は +3V3 を出す。接続する信号は 3.3V 系とする（H-13）。

#### 3.12.1 共通

| ID | 要求 |
|---|---|
| FR-J10-01 | J10_MODE（0x59）：0=未使用、1=ENC、2=HOME。既定 0。FR-NV の保存対象。起動時は設定を読み込んでから端子を設定する（それまではリセット時の状態のまま） |
| FR-J10-02 | J10_MODE の書き込みは停止中（パルス出力なし、原点復帰中でない）だけ受け付け、即時に端子を切り替える。動作中は CMD_RESULT=1。切り替えるときは一度アナログ入力に戻してから新しい機能を設定する |
| FR-J10-03 | 0=未使用：PA15・PA1 をアナログ入力にする（消費電流を抑える）。INPUT_STATUS bit0〜1 と ENC_COUNT は 0 |
| FR-J10-04 | PA15 はリセット直後 JTDI（JTAG）として内部プルアップ付きで設定されている。デバッグは SWD（PA13/PA14）だけを使うため、PA15 を他の機能に設定してよい |

#### 3.12.2 エンコーダ（J10_MODE=1）

| ID | 要求 |
|---|---|
| FR-ENC-01 | PA15 を TIM2_CH1、PA1 を TIM2_CH2（いずれも AF1、内部プルアップ）に設定し、TIM2 のエンコーダモード（両相の両エッジ、4 逓倍）で数える。オープンコレクタ出力のエンコーダも接続できるよう内部プルアップを有効にする |
| FR-ENC-02 | 入力にデジタルフィルタをかけ、ノイズによる誤カウントを防ぐ。各相 200 kHz（4 逓倍で 800 kcount/s）までの入力を数えられること。フィルタの値は config.h の定数とする |
| FR-ENC-03 | カウントは TIM2 の 32bit カウンタをそのまま符号付き 32bit として ENC_COUNT（0x5C）に出す。モード 1 へ切り替えたときと起動時に 0 にする。カウント方向は配線のとおりとし、ファームウェアでは反転しない |
| FR-ENC-04 | エンコーダの値は読み出し専用の公開だけに使い、モータ制御（脱調検出・閉ループ補正）・保護には使わない。ステップ位置（POSITION）との関係づけは上位側が行う |
| FR-ENC-05 | USB の名前表（FR-USB-37）に ENC_COUNT と J10_MODE を登録する |

#### 3.12.3 原点・リミット（J10_MODE=2）

HOME1（PA15）を ＋ 側（POSITION が増える方向）、HOME2（PA1）を − 側のリミット兼原点スイッチとする。FLAGS bit0（方向反転）に関係なく、POSITION の増減で ＋／− を決める。

| ID | 要求 |
|---|---|
| FR-HOME-01 | PA15・PA1 を GPIO 入力（内部プルアップ）に設定する。作動の論理は FLAGS bit4（0=アクティブ Low：NO 接点・オープンコレクタ向け、既定。1=アクティブ High）で両入力共通に決める |
| FR-HOME-02 | 入力は 1 ms 周期で読み、2 回連続で同じレベルなら確定する（確定まで最大約 2 ms）。確定した作動状態を INPUT_STATUS bit0（HOME1）・bit1（HOME2）に出す |
| FR-HOME-03 | リミット停止：パルス出力中に、進行方向側の入力（＋ 方向なら HOME1、− 方向なら HOME2）が作動したら、パルスを即停止する（ESTOP と同じ。励磁は維持）。INPUT_STATUS bit5 を 1 にする。FAULT にはしない。入力の確定から停止までを 1 ms 以内とする。「進行方向」は、パルス出力中の POSITION の増減方向で判定する（FLAGS bit0 の方向反転とは無関係） |
| FR-HOME-04 | 作動しているリミット側への移動指令（MOVE_ABS・MOVE_REL・RUN_SPEED・ジョグ）は受け付けず CMD_RESULT=1 とする（ジョグは動かさない）。反対側への移動は受け付ける。MOVE_ABS の方向は目標位置と現在位置の差で決める。次に受け付けた移動指令で INPUT_STATUS bit5 を 0 にする |
| FR-HOME-05 | 原点復帰：COMMAND 11 HOME_NEG（HOME2 側）、12 HOME_POS（HOME1 側）。ENABLED・停止中・J10_MODE=2 のときだけ受け付け、それ以外は CMD_RESULT=1。手順は (1) 指定側へ HOME_SPEED（加速度 ACCEL）で移動する。開始時にすでに指定側が作動していれば (3) から始める。(2) 指定側の入力が作動したらパルスを即停止する。(3) 反対方向へ START_SPEED（HOME_SPEED を超える場合は HOME_SPEED）で、入力が非作動になるまで移動し、非作動の確定で即停止する。(4) POSITION を 0 にし、INPUT_STATUS bit3（原点確定済み）を 1 にする |
| FR-HOME-06 | 原点復帰中は INPUT_STATUS bit2 を 1、STATUS bit0（MOVING）を 1 にする。STOP・ESTOP・DISABLE・通信タイムアウト（FR-MON-09）・FAULT で中止し、bit2 を 0、bit4（失敗）を 1 にする。(1) の途中で反対側の入力が作動した場合（スイッチの取り違え）、および (3) で START_SPEED により 1 回転分（STEPS_PER_REV × MICROSTEP ステップ）動いても非作動にならない場合も、即停止して失敗とする。新しい原点復帰を始めると bit3・bit4 を 0 にする |
| FR-HOME-07 | 原点復帰の完了で POSITION を再定義するため、SET_POSITION と同じく FR-POS-09 の自動 SYNC_POSITION の対象外になる（SYNC_POSITION と原点復帰のどちらを使うかは上位側が決める） |
| FR-HOME-08 | USB の名前表に、HOME1・HOME2 の確定レベル、INPUT_STATUS、原点復帰の内部状態を登録する |

### 3.13 ブートローダ移行（P2：ROM の USB DFU）

STM32L433 のシステムメモリにある ROM ブートローダの USB DFU で書き換える。自作のブートローダは持たず、アプリケーションの配置（0x08000000 から）とベクタテーブルは変えない。現在は S3（BOOT0）を押しながら S1 でリセットして DFU に入る。この操作を USB のコマンドで行えるようにする。

| ID | 要求 |
|---|---|
| FR-BL-01 | USB のコマンド ENTER_BOOTLOADER（0x50、PARAM は KEY u32 = 0x544F4F42）で ROM ブートローダへ移る。CONNECT 済みのセッションでだけ受け付ける。KEY が一致しなければ ERR 0x32 で何もしない。CAN（レジスタ・ブロードキャスト）からは受け付けない |
| FR-BL-02 | ENABLED 中（励磁中）は受け付けず ERR 0x33 を返す。NO_VM・DISABLED・FAULT で受け付ける |
| FR-BL-03 | 受け付けたら、まず ACK を送り、送信完了まで（最大 50 ms）待つ。次に、ドライバを安全状態（EN=Low、DMODE=000、DAC 最小）にし、RAM の指定領域（リセットで初期化しない領域）に移行フラグを書いてソフトウェアリセットする |
| FR-BL-04 | IWDG は一度起動するとリセットでしか止まらないため（ROM ブートローダは IWDG を更新しない）、リセット後のスタートアップで、IWDG・クロック・周辺を初期化する前に移行フラグを確認する。フラグがあれば消してから ROM ブートローダ（システムメモリ 0x1FFF0000）へ移る。フラグは一致する値（マジック値）のときだけ有効とし、電源投入時の RAM の不定値で誤って移らないようにする。フラグは SRAM1 のリセットで初期化しない領域（`.noinit`）に置く。SRAM2 は、オプションバイト SRAM2_RST の設定によってはリセットで消えるため使わない |
| FR-BL-05 | ROM ブートローダの終了（STM32CubeProgrammer の `-g 0x08000000`、または S1 リセット）でアプリケーションが通常どおり起動する。DFU の消去・書き込みはアプリケーション領域だけを対象とし、設定領域（0x0803F000〜、FR-NV-02）を消さない（セクタ単位の消去で 0x0803F000 未満だけを消す。手順は `firmware/README.md` に記載する） |
| FR-BL-06 | ROM ブートローダ中は PC15（CAN_S）が未設定の入力に戻り、TJA1441AT は内部プルアップでサイレントモードになる（H-8）。このため ROM ブートローダが CAN1（PB8/PB9）を有効にしても、ビットレートの違う CAN バスへエラーフレームを出さない。この前提は保ち、CAN_S の回路を変える場合は再確認する |
| FR-BL-07 | ROM ブートローダ中のドライバ制御端子の状態を確認する（H-14）。ROM ブートローダは USART・I2C・SPI の端子も設定するため、PA9/PA10（DRV_DIR/DRV_EN）、PB10/PB11（AGC）、PB12〜PB15（DMODE・RESET）が意図しないレベルにならないことを実機で確かめる。確認できるまでは、DFU は VM を切った状態で行う手順とする |

## 6. 試験項目（P1）

1. 電源投入時、EN/DMODE/DAC が安全状態であること（ロジアナ・テスタ）。手順：[test_poweron_safe_state.md](test_poweron_safe_state.md)
2. USB 給電のみで NO_VM を維持し、励磁しないこと。
3. VM 12 V / 24 V で VM_MV が ±2% 以内であること。
4. DMODE 各設定で 1 回転のステップ数が一致すること。
5. CLK 波形：パルス幅 ≥ 1 µs、速度 1〜100k step/s、加減速プロファイル。
6. DAC 電流設定：MOTVREF_TP1 の電圧が `I/1.25` に一致すること。
7. モータ線外し（OPD）で FAULT へ遷移し、CLEAR_FAULT で復帰すること。
8. 励磁中に VM を遮断して FAULT（低電圧）になること。
9. CAN：ID 0x100+ID で全レジスタ読み書き、32bit 書き込みの部分書き込みが無視されること。他局宛てのフレームに応答しないこと。ブロードキャスト ESTOP で全台が停止すること。
9a. CAN 終端：両端の 2 台だけ終端 ON のとき CANH–CANL 間が約 60Ω であること。終端の有無でエラーカウンタと波形を比較すること。
9b. CAN バスオフ：CANH–CANL を短絡して解除すると自動復帰し、LED_COMM の表示が正しいこと。
10. 通信タイムアウトで減速停止すること。
11. ウォッチドッグ：メインループ停止でリセットし、安全状態で再起動すること。
12. 設定保存：RUN_CURRENT=3000 などを書いて SAVE → 電源再投入後も保持され、CONFIG_STATUS bit0=1 であること。
13. 保存の繰り返し：65 回以上 SAVE してページ切り替えを跨いでも最新値が読めること。
14. 保存中の電源断：SAVE 直後に電源を切っても、次回起動時に前回値か新しい値のどちらかで起動すること。
15. 範囲外の書き込み（RUN_CURRENT=3500 など）が CMD_RESULT=2 で拒否されること。
16. 3A 設定で MOTVREF_TP1 が約 2.40V になること。3A 連続運転時の IC・TH1 温度を測定すること。
17. USB：USB 給電のみで仮想 COM ポートとして認識され、CONNECT・GET_VERSION・EXCHANGE_ID が応答すること。EXCHANGE_ID がビルドした ELF の build-id と一致すること。
18. USB フレーム：CRC 不正・LEN 範囲外・途中で途切れたフレームを捨て、次の正しいフレームに応答すること。CONNECT 前の要求に ERR 0x35 を返すこと。
19. USB メモリ読み出し：ELF から解決したアドレスの SET_MTA＋UPLOAD・SHORT_UP の値が SWD（ST-LINK）で読んだ値と一致すること。ペリフェラル領域・領域を跨ぐ要求に ERR 0x33 を返すこと。
20. USB 名前表：SYM_COUNT・SYM_INFO で全登録を列挙でき、SYM_FIND・SYM_UPLOAD で名前指定の値が読めること。未登録名に ERR 0x36 を返すこと。
21. USB の CAN 代行：試験 9 の CAN 要求をすべて CAN_REQUEST で行い、CAN と同じ応答が得られること。その間 CAN バスに応答フレームが出ないこと（CAN アナライザで確認）。FAULT 遷移時に USB へイベントが届くこと。
22. USB の影響：モータ 100k step/s 運転中に UPLOAD（240 B）を連続実行しても、CLK 波形が乱れず、LO 検出から EN=Low が 10 µs 以内であること。COM ポートを開かずに USB を接続したままでも動作が止まらないこと。
23. 位置センサの読み出し：AS5600 を接続し、軸を回して SENSOR_RAW・SHAFT_ANGLE が 0〜4095・0〜35999 の範囲で連続して変わること。PA7_MODE=1 で FLAGS bit2 を書くと PA7 のレベルが変わり、角度の増える方向が反転すること。SENSOR_OFFSET を書くと角度 0 の位置が動くこと。
24. 位置センサの異常：未接続で起動して SENSOR_STATUS bit3=1、SENSOR_RAW・SHAFT_ANGLE=0xFFFF になること。そのままモータを運転でき、FAULT にならないこと。後からセンサを接続すると 1 秒以内に有効に戻ること。磁石を外すと有効が 0 になること。
25. SYNC_POSITION：出力軸を既知の角度に置いて COMMAND 10 を送り、POSITION が `角度 × ギヤ比 × STEPS_PER_REV × MICROSTEP / 360°` になること（ギヤ比 20・40 の両方、分割 1 と 32）。MOVING 中は CMD_RESULT=1、センサ無効では CMD_RESULT=3 になること。モータを動かさずに起動したとき、センサが有効になった時点で自動的に POSITION が設定され、SENSOR_STATUS bit4=1 になること。モータを動かした後にセンサを接続しても自動では設定されないこと。
26. 位置センサの影響：モータ 100k step/s 運転中に I2C の読み出しが続いても CLK 波形が乱れず、LO 検出から EN=Low が 10 µs 以内であること。I2C の SDA を GND に短絡しても、メインループが 1 ms 以上止まらず、IWDG がリセットしないこと。
27. 位置センサの保存：GEAR_RATIO・SENSOR_OFFSET・FLAGS bit2 を書いて SAVE_SETTINGS し、電源再投入後も保持されること。範囲外（GEAR_RATIO=0、SENSOR_OFFSET=4096）は CMD_RESULT=2 で拒否されること。
28. PA7 の機能切り替え：PA7_MODE を 0/1/2 に書き換え、(0) AD_IN_MV が PA7 の入力電圧（±2%）を示すこと、(1) PA7 が FLAGS bit2 のレベルになること、(2) SENSOR_STATUS bit5 が PA7 の入力レベルに追従すること、を確認する。範囲外（3 など）は CMD_RESULT=2 で拒否されること。MODE を保存して電源再投入しても保持されること。モード切り替え中に I2C の読み出しとモータ運転が止まらないこと。
29. ホスト単体テスト（`firmware/tests/host/`）がすべて成功すること。試験 17〜21 のうちホストで検証できる項目（CRC16、フレーム受信、CONNECT 前の ERR 0x35、CONNECT・GET_VERSION・EXCHANGE_ID の応答、SET_MTA＋UPLOAD・SHORT_UP、ERR 0x33、名前表、CAN_REQUEST、CTR のエコー、送信詰まり 50 ms での要求破棄、イベントの上書き計上、FAULT イベント）を含む。
30. PC ツールの info・syms・get・read-var が実機で動作し、read-var の値が SWD（ST-LINK）で読んだ値と一致すること。

### 6.1 試験項目（P2：0.9 で追加）

31. AGC：FLAGS bit3 を 1 にすると AGC0/AGC1 が両方 High、0 で両方 Low になること（DISABLED 中）。ENABLED 中に bit3 を変える書き込みが CMD_RESULT=1 で拒否され、端子が変わらないこと。保存・再起動後も保持され、スタンバイ解除前に端子が設定されていること（ロジアナ）。
32. AGC の効果：AGC ON で FLIM しきい値以上の速度で運転し、軽負荷でモータ電流（電流プローブ）が下がり、負荷を増やすと戻ること。しきい値未満では電流が下がらないこと。AGC ON/OFF で LO 検出（試験 7）が同じに動くこと。
33. J10_MODE：0/1/2 の書き換えで PA15/PA1 の設定が変わること。動作中の書き換えが CMD_RESULT=1 になること。範囲外（3）が CMD_RESULT=2 になること。保存・再起動後も保持されること。
34. エンコーダ：A/B 信号（関数発生器 2 相、または実エンコーダ）を入れ、ENC_COUNT が 4 逓倍で増減すること。各相 200 kHz で数え落ちがないこと。モータの CLK 100k step/s 運転中も CLK 波形が乱れないこと。
35. リミット停止：＋ 方向へ移動中に HOME1 を作動させると 1 ms 以内（入力確定から）にパルスが止まり、FAULT にならず INPUT_STATUS bit5=1 になること。作動中の HOME1 側への移動指令・ジョグが CMD_RESULT=1 で拒否され、反対側へは動くこと。HOME2 と − 方向でも同じこと。FLAGS bit4 で論理が反転すること。
36. 原点復帰：COMMAND 11・12 で、スイッチまで移動→停止→戻って非作動で停止→POSITION=0、INPUT_STATUS bit3=1 になること。開始時にスイッチ作動中でも完了すること。途中の STOP・反対側の作動で中止し bit4=1 になること。繰り返し 10 回で原点位置のばらつきを測ること。
37. ブートローダ移行：USB 接続中に `nemadbg dfu` で DFU デバイス（0483:DF11）が現れ、STM32_Programmer_CLI で書き込み・`-g 0x08000000` で起動できること。書き込み後も保存設定が残っていること。ENABLED 中・KEY 不一致では移行しないこと。DFU 中に CAN バスへフレームが出ないこと（CAN アナライザ）。
38. ブートローダ中の端子：DFU 中に VM を投入し、DRV_EN・DMODE0〜2・DRV_RESET・AGC0/1 が Low のままでモータが励磁されないこと（H-14）。DFU 中に IWDG でリセットされないこと（1 分以上放置）。
39. ホスト単体テストに ENTER_BOOTLOADER の受け付け条件（未接続 0x35、KEY 不一致 0x32、ENABLED 中 0x33、受け付け時に ACK を返す）を加え、すべて成功すること。
